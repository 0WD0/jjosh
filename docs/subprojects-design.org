* 状态与结论

本文说明当前代码中的项目模型与保留的设计边界；日常操作见 [[file:workflows.org][工作流指南]]。
项目、不可变来源绑定、连接实例归属和转换观察已进入 operation-owned 状态，命令入口也已切换。
这不是“只把 projection 改名为 project”，也不表示结构化引用 scope 或任意项目布局迁移已经完成。

| 范围 | 当前状态 |
|------+----------|
| 项目登记、显示名、canonical 目录、稳定 label | 已实现；随 repo 部分恢复 |
| 不可变绑定、多个外部表示、连接实例身份 | 已实现；连接配置仍在本地 Git config |
| 转换观察、owner、raw/base/generation 证据 | 已实现；随 remote-tracking 部分恢复 |
| 显式迁移、格式隔离、本地 remote 变更恢复 | 已实现；升级须停止不兼容 writer |
| 独立 repository projection 与显式 preview | 已保留；不强制创建项目 |
| 完整结构化 scope、同名多 scope remote | 尚未实现，见独立提案 |
| 项目历史路径迁移、label 改名、嵌套项目映射导入 | 尚未提供通用命令 |
| 通用转换提供者注册系统、任意多目录可写项目 | 后续设计，不是当前类型或能力 |

模型划分如下：

- *项目* 是仓库内可独立选择、接收和交付的逻辑开发单元。
- *canonical 目录* 是其内容在完整提交树中的位置，不等于磁盘检出位置。
- *来源绑定* 明确说明外部历史如何表示这个项目；一个项目可有多个表示。
- *projection* 是历史与内容转换，不是项目类型，也不是另一套 remote 管理。
- *remote* 是真实连接与传输配置；名字、项目身份、来源上下文和写入授权不是同一件事。

不把项目永久分成“native 项目”和“projection 项目”。whole 表示可使用输入提供的原生状态；Josh filter/view 采用其过滤语义。

* 为什么需要这次切换

旧实现将 mount 私有 ref、按 remote 命名的 Josh sidecar 和 native provenance 混合用于项目登记及转换选择。
登记不属于 jj operation；同项目 peer 的 filter 一致性限制与普通 attach 的行为不一致；获取和发布可能选用不同 peer 的表示。
删除最后一个 filtered peer 后还可能退回纯目录导出，native anchor 也曾成为项目级算法分类依据。
这些是切换前的问题，不是当前行为说明。旧命令及旧配置不再是第二套运行时权威，只有显式迁移读取旧模型。

当前将项目布局与未挂载的来源表示分开保存。绑定从创建起不可原地换表示，fetch/push 按明确选择的绑定工作；没有绑定不能静默退回 whole 导出。
同一项目的不同外部仓库不必使用相同 filter；相同 filter 也不意味着可以共用 raw 上下文或 lease。

* 项目与 jj 核心概念

** 不是提交分区或子仓库

一个提交可以同时修改应用、lib 和构建脚本，仍是一份完整树、一个 change 的某个版本。
不同项目的交付书签可以指向同一提交；发布一个项目不要求先拆开本地整合提交。

“影响 lib 的提交”“从 lib 上游获取的提交”“发布 lib 生成的历史”是不同集合：分别需要内容查询、来源证据和选定转换的计算结果。
项目没有独立 DAG、HEAD、change ID 索引或 workspace；不会限制全局 new/rebase/squash 的作用范围。

** 不是工作副本布局

项目 =packages/lib/= 是 canonical 路径。workspace 可以将其映射到磁盘根，其他 workspace 仍检出完整布局。
=sparse= 负责检出和路径映射；project 命令不隐式创建 workspace 或调用 sparse。
原生导入的 =workspace/default#lib= 只是来源工作入口的普通书签。

** 当前内容范围

每个活动项目拥有一个非根 canonical 目录，不能与另一个活动项目的目录相等或互相包含。
未登记路径仍是普通仓库内容，不需要补一个 root 项目。项目可以在当前 revision 中没有文件。
登记只检查所选记录树中的路径，不要求目录在所有历史版本中存在；文件或 symlink 不能占用声明的目录位置。
路径参数通过当前 cwd 和 workspace 布局解析后保存为 canonical 路径，不保存 cwd 作为定义。

项目登记创建 operation，不创建源码提交、不移动文件、不 fetch，也不替用户快照新文件。
多个目录、重叠可写项目、任意历史布局迁移仍需单独的冲突语义设计。
项目不是构建系统 package、Git submodule 或访问控制边界；gitlink 不递归展开。

* 身份与生命周期

当前 [[file:../jj/lib/src/project.rs][project.rs]] 定义了三个仓库本地稳定 ID：

| 身份 | 含义 | 不代表什么 |
|------+------|------------|
| ProjectId | 一个开发单元 | 跨仓库 UUID、commit/change ID |
| BindingId | 一个不可变来源关系 | 可原地推进的配置版本 |
| ConnectionId | 一个本地连接实例 | URL 或 endpoint 身份 |

项目记录为 ={ name, canonical_root }=。改显示名保留 ProjectId、目录和引用 label；当前不允许原地改 canonical_root。
新项目不能因为重名、同 URL 或同 filter 就复用其他项目的身份。

remote rename 保留 ConnectionId。remove 后重新 add 分配新 ID，即使名字和 URL 相同；set-url 不更换绑定定义。
一个连接实例最多关联一个活动绑定，目标是一个项目或独立 RepositoryView。
多个项目使用同一 endpoint 时，需要不同 remote 别名；别名全仓库唯一。

remote remove 不注销项目，但会在新的 operation 中停用该连接的当前绑定。
恢复旧 operation 可以恢复绑定，不能恢复已删除的本地连接；同名新连接不会接管旧绑定。
反过来，保留受管连接而恢复到绑定尚不存在的 operation，会得到“绑定不可用”，不会退回普通 Git。

项目注销不删除文件或提交；必须先明确处理绑定、项目引用和 tracking 依赖。
=project resolve= 可选择冲突候选、解决显示名，或显式删除不再使用的定义/未连接绑定；它不是绑定迁移或重新接线接口。

* 一个项目的多个外部表示

当前绑定记录为：

#+begin_example
BindingRecord = { target, connection_id, representation, base }
target = Project(ProjectId) | RepositoryView
representation = Whole | JoshFilter(String) | JoshView(String)
#+end_example

这是当前具体类型，不是通用 provider/version 注册系统。BindingId 标识不可变定义，序列化格式负责编码版本边界。
核心保存声明和身份，不解析 Josh AST；绑定解析与历史转换由 jjosh 扩展执行。

项目导入可理解为 =L ∘ F=：F 将来源历史变成项目根坐标，L 将项目放到 canonical 目录。
发布先隔离项目内容，再根据明确 raw 上下文反向重建。有损过滤不一定有数学逆函数，不能把它写成简单的 =F⁻¹=。

例如同一个 api 项目可以绑定：

| 来源布局 | 显式表示 |
|----------+----------|
| 上游 monorepo 的 src/api | =--filter ':/src/api'= |
| 同布局 fork | =--like api-upstream= |
| 独立仓库根就是 api | =--whole= |
| 含未发布原生状态的本地 jj 仓库 | =--whole=，读取可用原生输入 |

=--like= 只复制目标归属、不可变表示和 base 选择规则，不复制 URL、写权限、tracking、raw 观察、resolved base、shallow 状态或 lease。
不能与 =--base= 同用；若同时给 =--project=，它必须与复制的目标一致。

带项目的 add/attach 要求项目已登记，且恰好选 whole/filter/view/like 之一，不猜测唯一 peer 的表示。
=--whole= 必须带项目；不带项目的 filter/view 表示独立仓库历史视图，不制造 root 项目。
已有绑定不可重写；要换表示或目标，创建新关系并明确处理旧状态。

whole 原生导入保留可用的 change 身份、有序父边、空提交、分叉和冲突；重新挂载改变 commit ID，失效签名移除并报告。
导出可以裁掉只影响其他项目的提交，不能将导入保真承诺扩写成“所有转换均保留每个空提交”。Josh 路径拒绝无法正确处理的原生冲突输入。

* 状态归属与恢复

| 数据 | 权威位置 | op restore 行为 |
|------+----------+-----------------|
| 项目、绑定、label、本地引用 | operation View | repo 部分恢复 |
| 远端观察、tracking、owner、转换证据 | operation View | remote-tracking 部分恢复 |
| URL/push URL、写权限、连接实例配置 | 本地 Git config | 不恢复 |
| raw 对象、normalization/provenance、endpoint lease | backend/来源存储与外部账本 | 不撤销外部结果 |

项目和绑定定义使用 =Merge<Option<T>>=，不是最后写入者获胜。
项目按整条记录合并；单边改名、相同改名可收敛，不同改名和删除/改名保留冲突。
同 BindingId 的不同定义是不合法输入，不是可以随便选一边继续用的配置更新。

身份逐键合并后还需派生诊断：同名不同 ID、重叠目录、同连接多绑定、悬空 label/绑定、观察 owner 不兼容等。
未解决记录的所有正项候选都参与名字和目录占用，不能只检查已解决项目。
诊断不成为另一份可变权威；相关项目/引用选择拒绝，无关健康项目仍可使用。
=project list/show/check= 显示离线诊断，=op diff/show= 的 View 差异也包含项目状态。

** canonical 目标不能替代来源证据

当前 View 分别保存 remote target 与 =project_observations=，后者是按 remote/name/kind 索引的带缺失项合并表达式。
每个不可变 ConversionObservation 保存：BindingId 和定义、被观察 ConnectionId、endpoint、完整 raw ref、带符号 canonical/raw 输入项、resolved base、normalization generation。
执行转换的绑定连接和被观察的发布目标连接可以不同，不能相互推断。

两个 raw 来源可能映射到同一 canonical commit；target 化简不能任取一个来源充当双方证据。
转换证据独立于 RefTarget 项数和顺序保留，canonical 不变而证据改变也会更新 operation。
恢复旧观察按其中的 endpoint/raw/generation/base 解释，而不是用当前 URL/filter 重新解释旧 canonical 目标。
缺失、不兼容或多义上下文会阻止相关发布，要求重新获取或明确选择 base。

当前 RemoteView 仍按 remote 名索引；新增 owner 校验没有把它变成 ConnectionId 主键。
同名新实例不能继承旧 tracking，当前也不能在一个别名下同时展示新旧实例的两份活动观察。
=git remote forget-observations NAME= 显式清除该别名的观察、tracking、owner、转换证据和缓存 mirror，再重新 fetch。
它不删除本地引用、项目/绑定、源码、来源对象或 endpoint lease；历史 operation 仍可保存旧状态。

** 格式与对象保留

新 operation-store 类型是 =simple_op_store_projects_v1=，与旧普通/sparse-aware 类型区分。
旧程序不能通过忽略 protobuf 新字段再写出丢失项目的 View；恢复空项目状态也不会降级类型标记。
旧 View 没有项目字段时保持旧散列语义，读旧历史不会从当前配置补造项目定义。

升级要求先停止不兼容 writer，再显式 =project migrate --apply --exclusive=；磁盘类型标记不能终止已打开旧格式的进程。
新版写入继续检查所需格式能力。
保留 View 中转换证据引用的 canonical commits 纳入 GC 根，来源对象和 generation 也必须保留以支持逆转换。
这不是任意并发 GC 的完整安全证明，也不能把私有来源存储视为可随意删除的缓存。

* 连接、来源上下文与发布授权

发布需分别确定：项目与 canonical 版本、来源表示与 raw 上下文、实际 endpoint/完整 ref/expected-old。
目的连接有匹配绑定时用它自己的表示；不能通过一次 push 偷换其绑定。
未绑定目的地要显式 =--source REMOTE= 选择转换来源，不能按“有 base 的唯一 peer”猜测。
来源只读不禁止向另一个可写目的地导出，也不会自动赋予目的地写权限。

=--base= 选择来源上下文，不代替 fetch 的分支选择或目标 lease。
Git 转换来源按 endpoint 保存 raw 对象、浅边界和 normalization generation；旧观察仍指向旧 generation。
=--fetch-url= 镜像只提供转换输入，不授权覆盖配置地址上的 ref。

新转换绑定默认只读；add 时 =--writable= 或 =--push-url= 可启用写入，显式 =--read-only= 优先。
attach 创建的绑定默认只读，发布需显式 =--writable=；普通 Git remote 保留普通行为。
真正的服务器授权仍由远端负责。原生 Git 可以直接访问真实 endpoint，绕过 jjosh 转换和本地策略。

显式和默认路由都检查所选项目、连接与来源证据；未加载必要扩展或恢复出的绑定不可用时拒绝，而非 raw Git fallback。
未登记的 =#后缀= 仍是字面名字，未受管普通传输保持普通行为。
colocated Git import 也需检查受管 mirror 的 owner/转换依据，物理 ref 名或相同 OID 不会自动成为可信来源事实。

发布先准备各目标，再开始网络写入；规范化 endpoint/完整 ref 碰撞在整批发布前拒绝。
=git push --dry-run= 从已准备计划显示实际 push endpoint、项目/label/目录、所选来源绑定与表示、resolved base（若有）及精确 expected-old/new raw target，不更新观察或 lease。
多个远端不是原子事务；网络或 receive-hook 后续失败可能留下已确认的部分成功，不能假定全部回滚。
转换发布只按实际 endpoint/ref 的精确 raw expected-old 更新；没有绕过保护的 =--force=。

* 引用 label 不是完整 scope

当前 =NAME#LABEL= 是过渡适配器，由 operation-owned 的 =label -> ProjectId= 关联解释。
登记前已有同后缀字面本地引用或远端观察时，普通 project add 拒绝接管；显式迁移列出接纳项。
普通 remote 或独立 RepositoryView 获取的 raw 引用若占用已登记项目后缀，会在写入 mirror/lease 前拒绝，不能仅凭同后缀就接管项目引用。
项目改显示名不改原 label，所以改名后的 api 仍可能使用 =topic#lib=。

尚未实现字面根名字与同拼写 scoped 名字的一等共存模型，也没有 scope-local remote 名空间、全局 =--project= 或随 cwd 缩小所有命令范围的隐式行为。
结构化引用见 [[file:scoped-references-design.org][独立设计]]。label 改名迁移、项目 fileset 专用语法和历史路径跟随不能被当成此次切换已交付的能力。

* 当前命令职责

| 任务 | 当前入口 | 不隐式做什么 |
|------+----------+--------------|
| 项目登记、检查和生命周期 | =project add/list/show/check/rename/remove/resolve= | 不配置 endpoint，不移动源码 |
| 原生开发状态作为外层项目导入 | =project import= | 不激活来源内部项目和连接 |
| 旧格式转换 | =project migrate= | 默认不写入，不猜旧观察来源 |
| 连接创建和生命周期 | =git remote add/attach/rename/remove/set-url= | 不原地换绑定表示 |
| 本地中断恢复、观察清理 | =git remote recover/forget-observations= | 不连接网络，不撤销发布 |
| 获取和发布 | =git fetch/push= | 不自动整合，不按改动目录猜交付对象 |
| 工作头与修改整理 | =new/rebase/squash/bookmark/tag= | 不创建项目专属 HEAD |
| 检出选择与布局 | =sparse/workspace= | 不改变项目身份和完整提交 |
| 临时转换求值 | =projection preview FILTER= 或 =--view PATH= | 不注册、不持久化、不接受 =--project= |
| 离线原生运输/图操作 | =native export/inspect/transplant= | 不自动成为项目配置迁移 |

add 仅创建，已有名字报错。attach 只为已有未使用普通 remote 增加明确表示，拒绝已有绑定或观察/tracking。
旧 =projection add/list/show/check/remote= 与 =native import= 已删除，不保留别名。
独立 projection 仍可用 =git remote add NAME URL --filter FILTER= 或 =--view PATH= 持续 fetch/push；不要用临时 preview 替代持久绑定或 push dry-run。

* 原生 bundle 与嵌套项目的边界

bundle v2 编码项目定义、绑定、label、连接 owner 和转换观察元数据；这些是惰性的来源元数据，不携带可激活的 URL/认证/写权限。
当前 project import 将整个来源封装成一个新外层项目，保留所需原生开发状态，不激活内部项目；多个来源可重复传入。
普通 Git clone 不会恢复这些 operation-owned 定义，native bundle 也不是包含旧 operation/evolution history 的完整备份。

“将含多个项目的仓库按内部项目逐个映射到目标”仍是另一项契约：需要明确源/目标 ProjectId、目录、label、绑定及重叠处理。
不能因为 bundle 已能编码元数据，就宣称已实现内部项目迁移或跨仓库身份同步。

* 迁移与本地失败恢复

=project migrate= 和 =--dry-run= 都只显示计划；=--apply= 才提交，格式升级还要求 =--exclusive=。
迁移物化旧默认目录，拆开 mount 与来源表示，列出接纳引用和将退出权威位置的 sidecar/private refs。
plain/filtered peer 混用有歧义时，用 =--representation REMOTE=whole|filter:EXPR|view:PATH= 明确选择。
无法证明 endpoint/raw/generation 的旧观察要求 =--clear-observations REMOTE=，保留本地引用和来源/lease 状态，之后重新 fetch。
旧 project-wide native 对应关系默认保留为 detached；也可用 =--native-source PROJECT=REMOTE= 明确归到同项目 whole 绑定，不由名字或当前 URL 猜测。

迁移保留有效 endpoint/refspec/认证和已有权限，不按新默认值重解释旧配置。
include/global remote 设置需先整理到本地；孤立 sidecar、无效路径/配置按计划诊断处理，不以重建默认 remote 掩盖。
新 operation 成为语义权威后，旧物理权威经恢复记录退出；工作文件、来源对象、浅边界和 endpoint lease 不因此被清除。
迁移的计划和 apply 期间都需停止旧版及原生 Git 并发写者；恢复 CAS 保护日志基线建立之后的更新，不覆盖盘点期间任意外部写入。=--exclusive= 是排除不兼容 writer 的确认，不是进程级 Git 全局锁。

本地配置、refs 和 operation 仍有不同提交点。remote 生命周期使用持久恢复记录而非宣称跨存储天然原子。
存在待恢复状态时相关变更/传输拒绝。=git remote recover --rollback= 在原 operation 恢复旧本地状态；=--accept= 校验当前绑定/owner 与预期后接受已提交状态并完成待处理工作。
恢复不访问网络、不刷新 expected-old；遇到不兼容的外部修改会拒绝。原生 Git 绕过 jjosh 的读写不在跨文件一致性保证内。
