#+title: Typed 本地引用：身份、语法与迁移提案
#+options: toc:2 num:nil

本文是尚未实现的本地引用模型提案，不是命令手册。当前项目、逻辑 remote、历史观察和本地传输边界见 [[file:subprojects-design.org][项目模型]]；可执行日常流程见 [[file:workflows.org][操作指南]]。

本文将“必须保留的现有合同”与“拟议的新接口”分开。typed 本地引用、组件级引用语法和 =--scope= 都属于提案，不应作为当前可用功能发布。

* 已实现的基线，不再作为未来目标

当前系统已经具备：

- 根与各 ProjectId 独立的 remote 命名空间、稳定 ConnectionId、不可变 BindingId；逻辑别名与 scoped 物理 handle 分离。
- repo-owned 当前项目、绑定、label、remote_names 和 remote_connections；remote-tracking-owned 引用、转换观察以及 observed 历史身份。
- 当前逻辑别名优先于历史别名，即使当前连接从未 fetch。历史可由显式物理选择器读取，不必激活旧项目、绑定或配置。
- 部分 operation restore 不回退 URL、认证、Git mirror 同步基线或 endpoint/ref 发布 lease；旧根观察归档，不覆盖重建后连接的记录。
- 多项目 fetch/push 的显式范围选择、项目内默认值隔离与整批预检，以及 nested/preserve 原生导入的不同状态合同。
- =simple_op_store_projects_v3= 的历史身份编码；v1/v2 可读，但写入须显式排他迁移。

这些是 typed 本地引用必须保持的行为，不是本提案才会修复的缺陷。现有逻辑／历史分离也不依赖本提案落地。

* 剩余问题：本地名字仍承担身份解释

当前 =View.local_bookmarks= / =local_tags= 以普通 RefName 为键。登记的 label 让 =main#engine= 表示 engine 的交付引用；未登记的后缀则仍是字面名字。显示名、label 和项目目录已有各自边界，但本地引用的项目归属仍需从字符串结合登记状态解释。

这留下三类问题：

1. 根中名字恰为 =main#engine= 的引用，与 engine 内的 main，不能作为两个独立本地身份无歧义共存。
2. parser、formatter、模板、补全、模式选择和存储层容易各自解释后缀；显示文本不能成为可靠的数据交换键。
3. label 登记、删除或迁移需要防止重新解释既有本地名字。历史不能依赖“今天登记了哪些 label”才能确定原来的引用归属。

目标是使本地引用归属成为结构化身份，并让语法只负责选取该身份。它不是按文件归属划分 commit，不建立每项目 DAG，也不自动消除同 change ID 的多个版本。

* 拟议身份模型

项目 scope 复用仓库本地 ProjectId；label 是选择／显示它的名字，不是身份。这里的“引用 ID”是结构化键，不是新增 UUID。

#+begin_example
RefScope = Root | Project(ProjectId)
RefKind  = Bookmark | Tag
LocalRefId { scope: RefScope, kind: RefKind, name: RefName }
RemoteRefId { local: LocalRefId, connection: ConnectionId }
#+end_example

root/project 与 kind 都参与比较、排序和去重。不存在基于显示字符串的等价判定，也不在本次提案中引入与项目无关的任意 named scope。

=RemoteRefId= 是正常逻辑身份的目标形态；兼容导入／原生 =@git= 等保留身份须有显式表示，不能假装拥有可联网的 ConnectionId。具体编码在实施前确定，但不能用当前 alias 字符串作兜底身份。已有历史观察继续保存自己的 ConnectionId，不引入第二套历史 remote ID。

scope 属于引用，不属于 commit。engine 的 main 仍可指向同时修改 engine、应用和构建文件的完整提交。唯一 DAG、heads、workspaces、change ID 索引与 operation history 保持不变。

每个 target 继续是完整 =RefTarget=，remote 继续保存 tracking。adds、removes、absence 与引用冲突必须无损保留，不能为了 typed key 简化为单个 OID。普通 change ID 的版本歧义保持 jj 现有处理；引用或 commit ID 选择具体版本。

项目路径、来源表示、base、引用 label 和 remote alias 是不同对象。移动检出布局不改引用身份，remote rename 不改 ConnectionId，项目显示名改动不迁移引用。项目撤销后的历史引用可以保留 ProjectId 而不激活项目；历史显示所需信息不能反向写入当前拓扑。

* 拟议文本接口

推荐外观仍是 =name[#scope][@remote]=，但 parser 和 formatter 按组件处理。以下是拟议 revset 语法，不是当前命令示例：

| revset 文本 | 拟议解释 |
|-------------+----------|
| =main= | 根本地 main |
| =main@origin= | 根 origin 的 main 观察 |
| =main#engine= | engine 本地 main |
| =main#engine@origin= | engine 的 origin 上 main 的观察 |
| ="main#engine"= | 根中名字恰为 main#engine 的本地引用 |
| ="feature#parser"#engine= | engine 中名字恰为 feature#parser 的本地引用 |
| =main#engine@"origin@inner"= | engine 内别名恰为 origin@inner 的 remote 观察 |

引号属于 revset 组件语法；传给 shell 时仍需独立保护整段参数。不能 split 格式化字符串恢复身份。名字里的字面 =#=、=@=、引号和转义必须可无损往返，bookmark/tag 选择保持原有类型区分机制。

显式 scope 无法解析就报错，不回退到根字面引用或 commit/change ID。当前工作副本符号 =@= 保持原义，不新增项目工作副本 ID。当前显式根 remote 选择器 =origin#= 的能力必须保留，具体与组件语法的组合需在 parser 接口中一次定义，而非在各命令中分别拼接。

历史 remote 的显式物理选择器继续作为兼容入口：它解析到观察身份，不是新的可配置 alias。formatter 在当前别名遮蔽旧观察或有同名历史候选时，须输出能选回原身份的形式；不能为了好看只显示 origin。

** 拟议命令范围规则

=--scope= 尚未实现。若采用它，本地引用命令遵守以下规则：

- 精确名字未限定 scope 时选择根；显式 =--scope engine= 才改变该命令内未限定名字的归属。
- 参数自带 scope 与命令 scope 不一致时报错，不静默覆盖。
- 修改／删除的名字模式只覆盖所选 scope；跨 scope 修改必须显式选择范围。
- 浏览集合默认保持全局。=bookmarks()=、tag 集合、日志、不可变历史、rebase、索引和 GC 不能漏掉项目 scope。
- 模板、排序、去重、补全和 operation diff 使用完整身份；需要显示用的 label 与存储 ID 分开传递。
- trunk 等仓库策略明确指定引用，不在多个项目的 main 中猜一个默认主线。

本地引用范围与传输范围不混为同一参数。现有 =git fetch --project A --project B= / =--all-projects= 的显式批量选择、排除根、独立默认值及预检不变；不能因为引入单个 =--scope= 而退回单项目 fetch。

现有 push 按所选引用 label 路由的行为改为按 typed scope 路由，结果应一致。=--remote fork= 仍在各项目内解释；项目不继承根默认值，缺少任一目的连接在网络写入前阻止整批。路由仍不看提交修改了哪些目录。

* 与转换和 tracking 的接口

typed identity 只改变引用的归属表达，不把以下三层合成一个字段：

| 输入 | 决定什么 |
|------+----------|
| LocalRefId / 所选 canonical 版本与引用动作 | 本地开发状态与发布内容 |
| 不可变 binding、raw 历史、base、generation | 转换来源坐标及逆转换依据 |
| endpoint、完整 wire ref、expected-old | 目标写入约束 |

** fetch 的边界

转换层输入明确的 source refs，输出结构化引用更新和独立转换观察；tracking 合并仍由 jj 完成。ObservationKey 向 typed 引用迁移时须保持 bookmark、tag 与 pinned revision 的区别；raw ref 和 endpoint 不因本地 scope 改名而改写。

选择／默认值／绑定预检在首个网络请求前完成；预检不保证网络阶段全成功。删除推断只覆盖本次完整观察的身份和范围，失败、未请求和未完成不代表删除。根 Git scanner 的扫描集与候选集继续排除 scoped 私有状态；=@git= 的内置身份不得变成导入来源的活动根连接。

同 change ID 的转换版本不能仅凭 ID 相同授权整份 canonical rewrite。设 C 同时修改 A、B，发布 A 后获取到 C'：A 子树相同不能证明 B 已发布。只有有效来源对应与转换边界支持的复用才可替换，其他合法版本和未发布工作必须保留。

** push 的边界

来源表示及 base 继续由绑定和保留观察决定，而非引用名字推导。目的已有内容时，逆转换保留 filter 外内容及 raw 父图；来源上下文歧义时选择具体版本或 base，不按 change ID 挑第一个。

lease 保持 endpoint/ref 的 raw 身份；typed scope 不刷新它，operation restore 也不回退它。annotated tag 保留直接对象与 peeled commit 的区别，签名对象改写后不能沿用签名有效性。

整批转换、可发布性及重复目的地检查保持在首个网络写入前。当前转换连接只允许选定方向一个 endpoint；typed 改造不能悄悄接受多个 push URL 却只处理一个。只有确认成功的更新推进对应记录，不声称跨 remote 原子发布。

* 操作历史、导入与本地配置

repo 侧保存 typed 本地引用及当前拓扑；remote-tracking 侧保存远端引用、tracking、转换观察及历史身份。只恢复 tracking 不能改当前 alias，也不能让导入／断开的观察成为活动连接。恢复后的引用与观察不得借当前项目目录或 URL 重新解释。

Git config 继续是地址、认证和 per-remote 设置的权威来源，scoped handle 继续复用 =jjosh-<ConnectionId>=；根名字保留原生 Git 兼容。typed 本地引用不增加第二份连接配置，不把 URL 或 endpoint 塞进引用身份。

nested 导入只安装来源历史 remote 身份，不占用当前 origin；preserve 保留可支持的当前项目连接与配置，也保留历史身份。两种模式都排除来源内置 =@git=，目标同步状态仍属于目标。迁移到 typed 引用不得降低原生导入对有序父边、空提交、冲突、divergence 和 change 身份的保真。

来源 raw 对象、浅边界、normalization 代际和不可重建的 provenance 继续由来源层保存。typed 引用的可见目标和 canonical 图不能替代它们；GC 根遍历必须纳入全部 scope 和保留观察，不能把来源存储当作可随意清空的普通缓存。

* 迁移合同：不重新解释旧历史

当前 v3 解决的是逻辑与历史 remote 身份分离，不是 typed 本地引用格式。typed 改造需要独立确定的新格式能力标记与显式迁移，不能未经升级就把新键写入现有 writer 认为是普通名字的字段。

实施前须给出完整转换表和恢复协议：

1. 依据旧 operation 的记录，把每个旧本地名字映射到明确的 Root 或 Project(ProjectId)，保留 kind 与原始名字组件；不是拿当前 label 状态套到所有旧 View。
2. 一并迁移 remote ref、tracking、ObservationKey、模板符号、默认策略和物理 ref 同步接口，不留两个解释入口并行猜测。
3. 映射有歧义、缺少历史依据或目的身份碰撞时要求显式映射／解决，不通过丢弃引用或将项目引用一律降为根来继续。
4. 保留 signed targets、删除项和历史归属，不改 commit DAG、change ID、raw OID、generation 或 lease，不自动合并 divergence。
5. 给不支持新模型的 writer 设置读写边界；旧对象按原编码保留散列。读历史不顺便合成新字段；新状态只能在明确迁移或变更边界写入。
6. 若要改 Git refs／配置，使用持久恢复日志及比较校验，覆盖中断、重复执行、锁冲突和并发 operation heads；单个 jj transaction 不是跨存储原子性。
7. 迁移成功且恢复路径成立后退役旧解释路径，不保留长期 alias shim。必须明确哪些旧版本还能只读，哪些须拒绝打开。

这不提供任意历史项目布局搬迁、不激活导入连接、不复制认证，也不回退外部发布。现有 =project migrate --apply --exclusive= 是当前项目格式迁移命令，不能提前宣称它已经支持本文的 typed 引用迁移。

* 验收条件与尚需确定的接口

以下验收混合了新能力和必须保持的既有行为，不是已通过的测试报告：

| 范围 | 消费者可观察的结果 |
|------+------------------|
| 身份与语法 | 根字面 main#engine 与 engine/main 共存；引号及分隔符往返不丢身份 |
| 命令选择 | 精确／模式修改不越界；显式冲突拒绝；全局浏览、维护不漏 scope |
| 历史名称 | 当前 B 在首次 fetch 前也不借旧 A 的记录；历史显式选择器仍准确可读 |
| 部分恢复 | repo 与 tracking 各恢复各的状态，配置、mirror 基线、lease 不回退 |
| 转换往返 | A 的发布保留 B 的未发布工作；相同 change ID 不触发未经证明的替换 |
| 获取与删除 | 部分 fetch 不删除未选观察，根同步不复活／清空 scoped 私有引用 |
| 发布安全 | filter 外内容、stale lease、tag 注释更新和重复目的地得到正确处理 |
| 原生导入 | nested 不激活历史连接，preserve 保持当前／历史分界，@git 不跨仓库迁入 |
| 存储与维护 | signed conflicts、浅来源代际和 provenance 保留；中断可恢复；旧 writer 不静默写回 |

尚需在实现前确定：保留 pseudo-remote 的 typed 表示、bookmark/tag 组件语法与现有 revset AST 的接口、typed scope 的跨范围模式语法、历史显示名的保存策略，以及有歧义旧引用的迁移映射输入。它们是本提案的剩余设计点，不是当前 remote 模型的待修复语义。
