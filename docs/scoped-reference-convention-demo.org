#+options: toc:nil num:nil

这条支线从 =tvptuwwt=（=dcb48c9c8561=）开始；之前的结构化 scope 重构保留在原提交链上，不是这个 demo 的前置依赖。

* 只改名字

native import 以及绑定项目的 git fetch 使用普通 jj 名字 =NAME#PROJECT=。包括本地 bookmark、tag、导入的 remote 引用和 =workspace/default#PROJECT= 工作入口。已登记 named remote 后，日常更新使用 =git fetch --remote REMOTE=，不再读取版本化 marker 的 source。

remote 仍用现有的全局名字 =PROJECT-REMOTE=：例如 =main#alpha@alpha-upstream= 和 =main#alpha@alpha-origin=。这里没有新的 symbol 类型、scope 语义、View 子树、存储格式或 =--scope= 参数；revset 现在把 =#= 视为普通名字字符。NAME 本身不被拆解，项目名仍沿用现有校验。

* 最小试用

先构建 =cargo build -p jjosh-cli --locked --offline=。下面的 source 是有 =main= 的已记录 jj workspace，upstream/fork 是与之对应的两个 *本地测试* bare repo；请换成自己的临时路径，不要在开发仓库或真实远端上运行。初次把已有状态接入时使用一次 =native import=，随后用 named remote 的统一 fetch/push 同步。

#+begin_src sh
jjosh git init --no-colocate --object-hash sha1 /tmp/demo-mono
jjosh -R /tmp/demo-mono native import --source alpha=/tmp/demo-source

jjosh -R /tmp/demo-mono link add alpha /tmp/demo-upstream.git --target main
jjosh -R /tmp/demo-mono git fetch --remote alpha-upstream --branch main
jjosh -R /tmp/demo-mono git remote add alpha-origin /tmp/demo-fork.git
jjosh -R /tmp/demo-mono projection remote attach alpha-origin alpha
jjosh -R /tmp/demo-mono git fetch --remote alpha-origin --branch main
jjosh -R /tmp/demo-mono bookmark track main#alpha@alpha-upstream main#alpha@alpha-origin
jjosh -R /tmp/demo-mono new main#alpha
# 修改 /tmp/demo-mono/alpha/ 中的文件，然后记录并选择发布版本。
jjosh -R /tmp/demo-mono describe -m 'project change'
jjosh -R /tmp/demo-mono bookmark set main#alpha -r @
jjosh -R /tmp/demo-mono git push --remote alpha-origin --bookmark main#alpha
jjosh -R /tmp/demo-mono git fetch --remote alpha-origin --branch main
jjosh -R /tmp/demo-mono log -r 'main#alpha@alpha-upstream | main#alpha@alpha-origin'
#+end_src

fetch、track、整合、publish 仍是独立步骤。普通 =main= 与 =main#alpha= 可以并存；local bookmark 的跟踪和重写沿用 jj，不建立一份新的同步状态。

* 明确不做什么

- 默认就是 =NAME#PROJECT=。旧的 =PROJECT/NAME= 观察可以暂时并存，新 fetch 下来后再删。
- =#PROJECT= 是命名约定，不是权限或归属隔离；相同拼写的“字面名字”和“带 scope 的名字”无法共存。导入会拒绝已占用的项目名字空间。
- named Git remote 保存真实 URL，Josh 文件只保存转换语义；项目身份和挂载属于 named remote 配置。多个 peer 分别配置，不从 =.link.josh= 的 URL/target 决定同步。
- 发布保留 jj 的显式选择和 tracking。bookmark 的创建、移动与 push 分开；push 根据选中引用的 =#scope= 自动导出项目并移除远端名字的 scope 后缀。发布 endpoint 不必绑定项目，fetch 的来源映射仍需配置。
- =jjosh git fetch/push= 执行所配置的转换；原生 =git fetch/push= 绕过转换并连接真实上游。没有 namespace façade 或原生 Git push 拦截器，不能把引用改名当作历史转换。
- 原有 native 转换边界、私有保活引用以及按实际 URL/目标分支绑定的 lease 均不变。这个 demo 不宣称解决所有转换歧义、隐藏版本或外部发布恢复问题。

* 验证

可直接运行自建临时仓库、清空环境且只访问本地 bare repo 的 CLI 集成测试：

#+begin_src sh
cargo test -p jjosh-cli --test native_import scope_suffix_convention --locked --offline
INSTA_UPDATE=no cargo test -p jjosh-cli --locked --offline
#+end_src

新增场景验证：普通 main 与带后缀的名字共存；bookmark/tag/workspace 及导入的 remote 引用保留 change 身份；两个 peer 使用普通 tracking；未变化的 fetch 不覆盖本地修改；只向 fork 发布项目内容，根目录修改留在本地；再 fetch 返回既有对应版本；Git import/export 和重新读取不改引用或 op-store 类型；占用名字空间的导入不发布操作。
